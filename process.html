build 各フェーズの詳細

企画フェーズ 必須
どのようにアイデアを出し、企画をまとめたか

　共働き・単身世帯の飼い主が抱える「通院時間の確保が難しい」「健康変化に気づきにくい」という課題を起点に、競合サービスの機能比較と不足点の整理を実施。そこから「健康記録」「異変の早期把握」「相談導線」を1つの体験に統合する方針を定め、MVPとして健康記録管理・予約管理・ユーザー管理を優先要件に決定した。

設計フェーズ 必須
設計時に意識したこと、工夫した点

　画面遷移は「記録入力までの操作数を減らす」ことを重視し、主要導線をトップページから2クリック以内に設計。データ設計では users / pets / health_records / appointments を中心に、更新頻度が高い項目と履歴項目を分離して保守性を確保した。APIはフロントの利用単位でエンドポイントを整理し、一覧・詳細・更新の責務を明確化して実装の複雑化を抑えた。

実装フェーズ 必須
実装で苦労した点、解決方法

　フロントエンドはHTML/CSS/JavaScriptでコンポーネントの再利用性を意識して構築し、フォーム入力時のバリデーションとエラーメッセージ表示を統一。バックエンドはSpring Boot + MyBatisでCRUD APIを実装し、SQLマッパーの責務を分離して可読性を維持した。予約・記録のデータ整合性で課題が出た箇所は、テーブル制約とサービス層での入力チェックを併用し、再現テストを追加して解消した。
